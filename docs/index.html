Post-training an agent
is a trade,
not an improvement.

MCP-AgentGym runs a real Kubernetes control plane with a deterministic workload simulator, so an agent's work can be graded by reading live cluster state instead of by another model. Across eight training arms and 2,200 episodes each, what post-training buys and what it costs are both large, both significant, and both bigger than every difference between the methods themselves.

The headline result

Training buys capability inside the catalogue and spends it outside

Every model is evaluated on 5,000 incidents none of them has seen, at n = 2,200 per arm, with zero id overlap with training. The Bonferroni threshold for the 42 comparisons reported is z > 3.0.

The untrained base model is the best agent in this project on fault families it was never trained for, and the worst everywhere else. That is not a small effect being over-read: both directions clear significance by a wide margin, and both are several times larger than any difference between SFT, DPO and the two GRPO variants.

The mechanism is countable, not speculative

Fine-tuning drives the two never-demonstrated diagnosis labels to 0 emissions in 599 submissions, against the base model's 25 in 501. Both labels sit in the submit_diagnosis enum and in the system prompt on every episode. The trained models are not blind to them; they can no longer reach them. What they emit instead is confidently wrong and drawn from the training catalogue: it answers readiness_probe_targets_wrong_endpoint for 17 of 32 NodeNotReady incidents.

That is label-prior collapse, not degraded reasoning, and the distinction decides the fix. Degraded reasoning needs better data. A collapsed prior needs the update attenuated.
The reversal

One knob, applied at serving time, undoes the trade

A LoRA update enters each layer as ΔW = (α/r)·B@A, so scaling lora_B by s scales the update exactly. s = 0 is the base model, s = 1 the trained one, and every value between is servable from a single engine by multi-LoRA.

No retraining, no second checkpoint, no data collection. The specialization the model acquired is a magnitude, and magnitude is a dial you can still turn after training has finished.

What it does not establish. The sweep does not locate an optimum, and the held-out axis is two fault families. A first pass predicted an in-distribution dip at s = 0.75 that a powered confirmation run failed to reproduce. It halved and stayed non-significant, which is textbook regression to the mean, and it was written down as a caveat when that job was submitted rather than after it came back.

The variance budget

The learning rate mattered more than every method tested

Before any method comparison means anything, you have to know what the same recipe does to itself. Every source of variation this project can measure, at n = 2,200 per arm on the same 5,000 fresh incidents:

Two floors, and the wrong one is easy to reach for

Two runs of the same configuration differ by 0.2 pp, which is GPU nondeterminism alone. Two independently trained models at seeds 11 and 12 differ by 3.1 pp. Method comparisons are the second case, and this project quoted the first as "the floor" for part of one session, which understated the relevant noise sixteenfold.

Which is why DPO cannot be quoted as a number

Trained from two baselines that were identically configured and scored within 0.2 pp of each other, DPO gave +4.18 pp (z = 2.83) once and −0.27 pp the other time. The disagreement is twenty times the evaluation floor, so it is not measurement noise. The variability is in training. DPO can help by a wide margin; a single run's gain turns out to be a property of that run.

The best agent in the whole grid is a plain supervised fine-tune that happened to train at the better learning rate: 57.7% resolution and 0.01% invalid calls, beating every post-trained variant. It is not a post-training result. It is the absence of one.

How it works

Split the stack where the agent actually operates

Post-training needs thousands of resettable, seeded, parallel episodes with verifiable rewards. A real Kubernetes cluster gives none of those: episodes take minutes, never reset cleanly, and are nondeterministic, so the same action earns different rewards on different runs. That is fatal for DPO preference pairs and GRPO advantages alike.

So the split is made at the API boundary, which is exactly where an agent works anyway. The control plane is real. The kubelet is replaced by a deterministic workload simulator that computes pod status from declared physics. What that buys: sub-second resets, hundreds of parallel episodes per node, bit-exact reproducibility from a seed, and rewards that are computed rather than graded.

What is real, and what is simulated

etcd · apiserver · controller-manager · scheduler
real
Genuine CRDs, RBAC, admission, watch and reconcile. Deployment→ReplicaSet→Pod is real, and so are scheduling, taints and Unschedulable. v1.31.4, as unprivileged user processes.
MCP protocol
real
The reference mcp library over JSON-RPC. A standard MCP client drives this environment unchanged.
kubelet / container runtime
simulated
Pod status computed from declared workload physics: resource fit, image validity, config presence, probe configuration. Deterministic and instant.
Traffic, health, metrics, logs
simulated
Health is a pure function of cluster state, which is what makes the verifier exact rather than approximate.
The expert
scripted
Not a model. It is the reference ceiling and the SFT demonstration source: 91.4% resolution over 4,010 episodes, and always reported as a scripted policy.

Rewards nothing judges

Every term is read from live cluster state, a JSON Schema, or the gateway's call log.

score = 2.0·resolved
      + 0.5·root_cause_correct
      + 0.4·validated
      + 0.2·recovered
      − 0.05·unnecessary_calls
      − 0.3·invalid_calls
      − 0.8·unsafe_actions
      − 0.1·over_budget

The unsafe penalty is sized so that a well-formed forbidden action scores below emitting nothing parseable at all (−0.5 against 0.0). A smaller one would leave the model better off confidently deleting a pod than staying quiet, which is the wrong lesson for an agent holding production credentials. A test asserts that ordering.

Robustness to tool-schema shift

Retention = resolution under the perturbation ÷ that variant's own clean resolution, so the tool surface is the only thing that varies.

Post-trained models are far more robust than base to a renamed tool, a renamed argument, and distractor tools. They learned to read the schema rather than recall names from training. Nobody survives a tool that disappears: even a policy reading the schema perfectly retains 0.74, because a withdrawn tool cannot be called by anyone.

Serving

Prefix caching does not just help agent workloads; it compounds with them

One L40S, Qwen3-8B, with the real 36-tool system prompt, at 32-way concurrency. The synthetic conversation deepens exactly as an episode does, so the shared prefix grows while new tokens per turn stay small.

Why believe any of it

The same discipline retracted five of this project's own claims

Each of these was published in this repository, then contradicted by a later run and withdrawn, along with the defect that caused it and the assertion that now prevents it. The withdrawn trajectories are quarantined, not deleted.

"DPO improves resolution by +8.2 pp"
+2.1 pp under adequate power, and never significance-tested when first published. Winner's curse: the effect shrank monotonically as n grew while z stayed pinned near 1.5.
"More preference pairs produce a better policy"
A 437-pair replication scored identically to the 88-pair run. The original +11.0 pp was run-to-run variance, and the difference had never been tested.
"Episode-GRPO damages the tool-call format SFT taught"
An artifact of an adapter initialised two versions behind its own training data. The mechanism story was plausible, internally consistent and entirely wrong; a weight-digest lineage check caught it.
"One extra SFT epoch outweighs every post-training method"
Confounded. Isolated, the epoch alone is −4.1 pp; the gap belonged to a difference between the two adapters.
"Seed variance is 15.6 pp and swamps every comparison"
It was the learning rate. No launcher ever forwarded --seed, so every adapter this project ever produced had trained at seed 0. The seed had never been varied at all.

The guards are in the code, not the prose

A claim in a document is worth what the assertion behind it is worth. The report script refuses to render a partial grid. One test asserts every tool count quoted in the docs matches the registry; another that the serving numbers are recomputable from their raw artifacts. Training records a weight digest of its base adapter, which is how the withdrawn GRPO run was caught. build-datasets refuses to overwrite the corpora the published results were trained on.

And since the seed defect: a test asserts that every result-bearing argument a trainer accepts is reachable from its launcher. Its first version was defective in exactly the way it exists to prevent. It searched the raw file, and the comment explaining the fix contained the flag, so deleting the real argument left it passing. It strips comments now, and the failure was verified by deletion.

What the project does not claim

Any ordering among SFT, DPO and the two GRPO variants. Every arm is a single training run, and with a 3.1 pp floor between independently trained models, method effects of 2–5 pp sit inside it. The grid establishes that post-training works. It cannot establish which method is best, and resolving that needs several seeds per arm.

Anything about a second base model. Everything here is Qwen3-8B.

Live cloud behaviour. The S3 paths are tested against moto and the EKS overlay renders and diffs in tests. Neither has been run against a real account, and the page says so rather than implying otherwise.

That any single evaluation run is reproducible. The same untrained weights, the same incidents, temperature 0, differing only in which vLLM instance served them: the tool sequence reproduced in 0 to 1 episodes out of 100, and about a fifth of resolve/fail verdicts flipped. Continuous batching makes greedy decoding depend on batch composition, and an agent harness turns one divergent token into a different investigation. Comparisons within one sweep are unaffected, since one engine serves every arm; paired per-incident comparison across runs is not valid, and the 0.2 pp floor is a same-configuration large-n figure that understates small-n noise by more than an order of magnitude.

Every increase in rigour moved the answer toward "no measurable difference", right up until the learning rate was matched. At that point DPO reappeared on one baseline and not the other. Both halves of that belong in the record.
