SURVIVES SCRUTINY
-----------------
(a) Post-training clears the untrained base on every arm, z >= 3.99, at
    n=2,200/arm on 5,000 incidents no model has seen (zero id overlap with
    training).

(b) Invalid tool calls collapse 26.32% -> 0.01-0.35%. A ~100x effect; nothing else
    in the project comes near it.

(c) Post-training is a TRADE, not an improvement. Base is the BEST model here on
    fault families it never saw (65.8% vs 33-53% for everything trained).
    +16.2pp in-catalogue capability (z=10.96) for -27.6pp held-out (z=-19.06).

(d) The mechanism behind (c): fine-tuning drives never-demonstrated diagnosis
    labels to 0 emissions in 599 submissions (base: 5.0%), though both labels sit
    in the tool schema and system prompt on every episode.

(e) (c) is REVERSIBLE at serving time without retraining. dW = (alpha/r)*B@A, so
    scaling lora_B by s scales the update exactly:
        s=1.00 -> 36.7% held-out,  0/114 labels emitted
        s=0.75 -> 50.8%,           8/112
        s=0.50 -> 72.5%,          24/56
    Monotone, z=5.97 end-to-end, no measurable in-distribution cost, and it
    REPLICATES on a second independently-trained adapter family to within 1.6pp
    (SFT: 35.8% -> 70.0%, z=5.65).

(f) The run-to-run floor is 0.2pp at n=2,200 (two identical-config runs: 57.7% vs
    57.5%, z=-0.12). NEW this session — see section 3.

(g) 0 unsafe actions in 3,840 post-trained episodes.

(h) Environment correctness asserted per fault family; sim-to-real 5/5 on the
    process layer (healthy, OOMKilled, BadConfigMap, ReadinessProbeMisconfig,
    CascadingDependencyDown), agreeing on BOTH readiness and reason.

    NEAR MISS WORTH KEEPING: pair 1 was complete for a full cycle before pair 2

3. THE BIG CORRECTION OF THIS SESSION — READ BEFORE TRUSTING OLD NUMBERS
================================================================================

ROOT CAUSE: no launcher ever forwarded --seed.

  All three trainers (sft/dpo/grpo_train.py) accept --seed and use it.
  slurm/*.sbatch never passed it. Three jobs submitted with SEED=1 / SEED=2 all
  trained at seed 0 — training_args.bin proves it.

  => EVERY ADAPTER THIS PROJECT HAS EVER PRODUCED TRAINED AT SEED 0.

WHAT THAT INVALIDATED:
  A "+15.6pp seed variance (z=10.48)" was published as the largest effect in the
  project and as the reason method comparisons were called uninterpretable.
  It is a LEARNING-RATE effect: v4 used 5e-5, the newer runs 1e-4. The two runs
  sharing an LR agree to 0.0005 in train loss.

WHAT REPLACED IT:
  - The dominant controllable factor is the learning rate, and the published
    baseline trained at HALF the better one. Every method comparison in the docs
    was measured against an undertuned reference.
  - The true floor, measured for the first time: 0.2pp at n=2,200.
  - Method effects of 2-5pp are 10-25x the floor => READABLE.

ALSO FOUND: train_dpo.sbatch never passed --lr either. DPO's learning rate was
  always the trainer default; exporting LR did nothing.

GUARD: tests/test_launcher_plumbing.py asserts every result-bearing argument a
  trainer accepts is reachable from its launcher, and that each carries a default.
  Its FIRST VERSION was defective in the way it exists to prevent — it searched the
  raw file, and the comment explaining the fix contains "--seed", so deleting the
  real argument left it passing. It strips comments now; failure verified by
  deletion.

A SECOND SUBTLETY WORTH KEEPING:
  Training here is LOSS-REPRODUCIBLE but WEIGHT-DIVERGENT. Two identical-config
  runs are 138% apart in relative lora_B norm while agreeing to 0.0005 in loss and
  0.2pp in evaluation. So weight distance is NOT evidence of behavioural
  difference — but it IS a sound lineage check, and that is how the withdrawn
  episode-GRPO run was caught.

  Corollary: per-split differences are NOT the floor. Those two runs differ by up
  to 9pp on a single 500-700 episode split and by 0.2pp pooled at 2,200. Quoting a
  per-split gap as run-to-run noise overstates it tenfold — that is where the
  "11pp floor" this project carried for weeks came from.

7. RULES LEARNED EXPENSIVELY — DO NOT RELAX THESE
================================================================================
  - Never read a partial grid and draw a conclusion. This project reversed twice
    by doing exactly that.
  - Significance-test everything. Bonferroni when reporting several comparisons.
  - Per-split differences are NOT the run-to-run floor. Pool first.
  - Verify an adapter's base by weight digest before evaluating it.
  - Never delete data. Withdrawn results -> runs/eval-withdrawn/ with a README.
  - git commit -F - with a heredoc. NEVER -m with backticks: bash
    command-substitutes them, and pip output once landed inside a commit message.
  - Commit locally only. Never push.
  - home quota ~1GB. Install nothing large. Never touch ~/.cache/huggingface.
  - generator version=1 must stay reproducible; a test pins it. version=2 is
    prefix-stable, so the pool can grow without renaming anything.
